# [Jev](https://typesafe.ai/) Live Evaluation: 2026-10-08

## Scope

This is a single-model live evaluation, not a comparison with the production
model. No production MCP search requests, embedding calls, or existing reranker
calls were made. Production code and database contents were not changed.

The production log database contained 16,340 search records when checked.
The experiment sampled 80 unique actual queries from the latest 1,500 records
(source window: 2026-08-26 through 2026-10-08). Half were recent unique queries;
half were evenly spaced across the remaining records.

Real document candidates came from the production corpus through read-only
lexical queries over an SSH connection. The final preparation produced 866
candidates, no retrieval failures, and 105 marked, truncated excerpts.
This is not production hybrid recall: there were no semantic-model calls.

## Three Primitives In One Request

Each query used one shared state containing its original text and candidates:

- `Score`: four relevance grades for each document.
- `Noul`: direct usefulness for each document and overall answerability.
- `Choice`: best document, including an explicit `none` option.

All these questions were submitted together. The 80-query run requested 1,892
decisions. Expected question IDs, answer types, legal choices, and numeric
ranges were checked. No invalid answer shapes were observed.

Model confidence is not an independently measured correctness percentage.

## Small, Independent Relevance Controls

Six actual queries were paired with directly matching real documents. The same
queries were then paired with unrelated real documents. Expected labels were
not included in the request.

Using the handoff's uncertainty band (`0.4 <= Noul <= 0.6`):

- 11 controls produced the expected clear decision.
- One negative control was uncertain.
- No clear false positives or clear false negatives occurred in this small set.
- `Choice` selected the matching document in all six positives and `none` in all
  six negatives.

The uncertain negative paired a simulator-runtime installation query with an
alarm-scheduling sample. Its Noul usefulness was 0.51, but Score was 0.64/3 and
Choice selected `none`. This is a concrete reason not to treat the three
primitives as interchangeable certainty measures.

The controls are deliberately obvious and small. They do not establish general
search accuracy or a domain-wide recall/precision score.

## Repetition And Order

Ten queries were probed: five rejected-candidate queries and five where a
document had been selected. Each was replayed in original and reversed order.

- Best-document identity remained unchanged in 19 of 20 probes.
- The mean absolute score change was 0.0625 on the 0-to-3 scale.
- One reversed-order probe switched between two substantially equivalent
  simulator-runtime installation documents with different URLs.

Manual inspection of both documents confirmed that the switch was not clearly
a semantic degradation. Still, exact identity and floating-point predictions
should not be assumed deterministic.

## Qualitative Checks

The model selected clearly useful sources for alarm scheduling, test migration,
model-data management, simulator-runtime installation, and backup exclusion.

The main run selected `none` for 58 of 80 queries. Only seven queries received
answerability at least 0.6. These are model judgments about this supplied
candidate pool, not measured failure rates.

There are important distinctions:

- A corpus retrieval miss cannot be fixed by choosing among supplied passages.
- A useful partial passage is not necessarily enough to answer the whole query.
- Best-choice confidence describes selection among these options; it does not
  certify the completeness of the selected document.

For example, an external-storage filesystem/mounting query selected
[AVExternalStorageDevice](https://developer.apple.com/documentation/avfoundation/avexternalstoragedevice)
with choice confidence 0.83 and usefulness 0.71. The supplied 370-character
passage describes external media storage, but does not specify filesystem or
mounting requirements. Answerability was only 0.05. It is a weak supporting
passage, not a complete answer.

A toolbar query selected a web-navigation example. Inspection showed that its
body actually contains both `ToolbarItemGroup` and `primaryAction`; the different
page title alone is therefore not proof that the choice is wrong. The model
reported 0.50 answerability and 0.56 choice confidence.

A preliminary unbounded lexical sort hit the database statement timeout.
Preparation was changed to strict terms followed by a bounded relaxed pool,
then retried successfully. These were retrieval-preparation problems, not
model API failures. No database configuration was changed.

## Conclusion

The model successfully handles this batch of typed decisions at low input cost
and reasonable observed latency. The evidence supports its usefulness as a
candidate-scoring component.

It does not demonstrate a standalone replacement for retrieval, nor justify
turning answerability or confidence directly into automatic rejection of user
queries. No other model was evaluated, and no production migration was made.
