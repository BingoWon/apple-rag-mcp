# CLI authorization interface refresh — 2026-11-03

Service 5.5.3; npm CLI 2.0.1. This fixes the hosted authorization, related website
login screens, CLI callback screens and CLI access settings. Authentication and
shared subscription/quota boundaries are unchanged.

## Design and implementation

- One compact authorization surface: neutral Apple RAG wordmark, restrained blue
  primary action, 460px maximum width, clear heading/body/helper hierarchy and
  consistent light/dark palettes. The website and self-contained loopback HTML
  share `shared/auth-presentation.ts`; no new production UI dependency was added.
- Account and device are separate identity rows. Permissions and shared-quota
  information are readable before consent. Device-code matching, cancellation,
  expiry, progress and success have explicit states. The website passes its chosen
  language/theme to the local callback using presentation-only query parameters.
- The loopback returns a complete localized HTML document instead of raw text.
  Success is emitted **after** code exchange and protected credential persistence.
  Storage failure renders an error, revokes the new grant and never reports success.
  State, issuer, Host, loopback and PKCE validation remain enforced; CSP/no-store/
  no-referrer headers protect the local document. No remote scripts/fonts/assets
  are needed and authorization codes are not reflected into the HTML.
- CLI settings emphasize the connected-device list and a copyable login command.
  API-key creation and one-time key display use the existing Radix Dialog, Input
  and Button components. Revocation identifies the affected device and asks for
  confirmation. Closing the one-time dialog clears its displayed key.
- Missing semantic helper-text colors are now defined. Primary/destructive controls
  use legible contrast; shared controls remove heavy outlines/bounce. Button loading
  preserves text and exposes `aria-busy`; slotted links remain valid. Inputs finally
  render their supplied labels, errors and helper descriptions with associated IDs.
  Existing auth forms share the same shell instead of nesting bordered cards.

## Verification

- Full lint/type checks and build pass: 220 application/PostgreSQL tests and 16 CLI
  tests. New regressions cover slotted buttons, persistent loading labels, input
  associations, escaped/self-contained callback HTML, all callback result states,
  and failure to save credentials before a success page can be shown.
- `ops/ui/check-cli-auth.mjs` runs headless Chrome against the built website and
  actual callback HTML renderer, with isolated local HTTP fixtures and fake
  `.invalid` account data. It checks English/Chinese, light/dark, 320/390/1440px,
  145 layout/state cases, keyboard focus, loading, approval/denial/expiry, device codes, key creation and
  one-time dismissal, revocation and the unauthenticated login return path.
  Screenshots and the results ledger stay in ignored `ops/ui/results/cli-auth/`.
- Browser inspection caught a hidden header-menu overflow on narrow screens and
  a slotted-button render error; both were fixed before release.

## Release and scope

Main push deploys the website/Worker; GitHub CI publishes CLI 2.0.1 only after
production 5.5.3 is ready. The callback page lives in the installed CLI, so an npm
upgrade is required to replace the old plain-text callback. Existing Keychain
sessions remain usable across this patch. The owner's active grant is not revoked
for visual checks. No production subscription, account or API key is created or
changed by browser fixtures. Broader dashboard/admin redesign is outside this change.
